# 本番DB接続の再利用

本番では、利用済みの接続を最大30分間、未使用のまま接続プールに保持する。従来の5分より長く保持し、アクセスの間隔が5〜30分の場合のTCP/TLS再接続を減らす。

- `idle_timeout: 1800` は本番だけに適用する。30分を超えて未使用の接続はRailsの定期処理で解放されるため、厳密に1800秒で切断されるわけではない。
- 接続は必要になったときだけ開く。最小接続数は0のまま、上限は従来どおり各ワーカーで `RAILS_MAX_THREADS` 本。現在の2ワーカー・5スレッドでは最大10本で、Aivenの上限76本以内に収まる。別のdynoや管理用接続は別途数える。
- Rails標準の接続確認・再接続とkeepaliveを使う。現在のMySQLの `wait_timeout` は28800秒。接続先やサーバー側の待機時間を変更する際は、保持時間と再確認する。
- `ssl_mode: verify_identity`、CA検証、最小権限の実行ユーザーを維持する。新規サービス・環境変数・DB移行は不要。
- Eco dynoの停止・再起動、DB側の切断、30分以上の待機では新しい接続が必要になる。この設定による月間の接続回数や料金の削減は保証しない。

## 検証

`spec/services/database_connection_reuse_spec.rb` では、隔離したMySQLで実際に接続し、未使用時間を再現して10分後の再利用・30分超過後の解放・切断済み接続からの回復を確認する。試験用のトランザクションによる接続の固定は無効にしている。

Issue: https://github.com/yu-yaba/gatareview-back/issues/55

比較試験では、同じデータと6回の読み取りを使い、10分の待機を再現した。TCP/TLSとSQLは実通信し、透過中継でパケットの内容を保存せずバイト数だけを数えた。変更後には保持した接続へのkeepaliveの通信も含めた。

| 項目 | 変更前 | 変更後 |
| --- | ---: | ---: |
| TCP/TLS接続数 | 6 | 1 |
| 双方向の通信量 | 38,678 bytes | 9,826 bytes |
| 接続取得・読み取りの中央値 | 48.56 ms | 1.07 ms |

待機時間の判定を再現したローカル試験の結果であり、本番のネットワーク遅延や月間の削減量を示す値ではない。
